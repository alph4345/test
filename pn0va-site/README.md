### Which one goes on the server

**`*-clean`.** Each page becomes its own folder with an `index.html` inside, so
`pn0va.com/drops` serves `drops/index.html`. That means pages sit one level
deep, so every asset path is **root-relative** (`/style.css`, `/images/...`) —
which is exactly why opening one by double-clicking shows an unstyled page:
`/style.css` resolves to your drive root. Use the flat build for that.

A `.htaccess` ships with each clean build. It strips trailing slashes, maps
bare paths to their `index.html`, and 301s every old URL — including
`geocache.html` → `/drops`, since that page was renamed, not just re-pathed.

Both are generated by `build.py` from one source, so they cannot drift apart.
**Edit the build script, not the output folders** — re-running wipes and
regenerates both.

```bash
python build.py
```

It needs two things, and finds both on its own:

| | Where |
|---|---|
| The 2026-07-06 build it derives from | `_source/website-fixed/` (bundled here) |
| The brand kit | `Desktop\PN0VA` — the sibling folder |

Change anything in `PN0VA` and re-run; both variants pick it up. The source is
bundled rather than referenced so this folder stays self-contained and the
script keeps working years from now.

## What changed from the 2026-07-06 build

**Branding**
- Corrected logotype — katakana now **ピー・ノバ** everywhere, including the
  raster art. `logo.svg` is outlined so it needs no font installed; the sprite
  atlas driving the animated homepage logo had its `ーバー` cell repainted to
  `バ` (the glyph cut from the original art, so the font still matches); and
  `logo2.png` / `logo.png` were regenerated from the corrected vector.
- **The no-JS fallback logo is now visible.** `logo2.png` was 100% black,
  displayed on the black homepage with no filter — so with JavaScript off the
  homepage showed nothing at all. It is now red.
- Palette migrated to the brand kit. Body copy came **off pure white onto
  linen** `#E8E2DC`, which is what lets bone `#FFFFFF` mean *you are here*.
  Yellow is gone entirely — state went to bone, the `h3` sub-headings went to
  the chroma. Greys warmed to taupe/ash.
- Fixed the two drifted reds (`#ff1608`, `rgba(255,22,8,.5)`).

**Structure**
- `geocache.html` → **`drops.html`**, and ~550 lines of dead `geo-*` CSS
  stripped out. Nav and home menu rewritten on every page.

**No more CDNs.** The site now makes **zero external requests**:
- Press Start 2P is self-hosted from `fonts/` — which also removes the
  `@import`-ordering trap that once stopped the pixel font loading at all.
- CreateJS is vendored to `vendor/` — `index.html` already carried fallback
  code for that CDN failing, which tells you it had.

## The store was rebuilt, not recovered

**`shop.html` did not survive.** (It is `store.html` now — renamed 2026-08-02.) It isn't in `website-fixed.zip`,
`website-clean-urls.zip`, `files (2).zip`, or anywhere on the Desktop. Your
`PROJECT-HISTORY.md` explains why: the dev container reset partway through that
session, the site was restored from the packaged zips, and the shop was layered
back on afterwards — so it only ever existed in a container that no longer
exists.

What ships here is rebuilt from the description in that history, and matches it:

- Card grid, `auto-fill minmax(280px, 1fr)`; 4:3 image, name, glowing price,
  unlimited-length description, ADD TO CART pinned to the card bottom
- Floating CART button with a count badge that pulses on add
- Slide-in panel: qty +/−, remove, subtotal; closes on Esc or backdrop
- Persisted in `localStorage` under **`pn0va-cart`** (same key as the original)
- Items are pure HTML with `data-id` / `data-name` / `data-price`
- `SQUARE INTEGRATION POINT` comment marks where `checkout()` gets replaced;
  the cart is exposed as `cartLines()` and `total()`

Product copy and images are placeholders. **The three `data-id`s are made up** —
if the original shop ever resurfaces, reconcile the ids before going live or
returning customers' saved carts will mismatch.
