# pn0va.com — 2026 build

Rev **2026.08.02**. Four builds — two variants x two URL styles:

| Folder | URLs | |
|---|---|---|
| `with-store/` | `/caches.html` | Flat. Double-click previewable. |
| `with-store-clean/` | **`/caches`** | Folder-per-page. **Must be served.** Upload this one. |
| `no-store/` | `/caches.html` | Same, store removed everywhere |
| `no-store-clean/` | **`/caches`** | Same, store removed everywhere |

### Which one goes on the server

**`*-clean`.** Each page becomes its own folder with an `index.html` inside, so
`pn0va.com/caches` serves `caches/index.html`. That means pages sit one level
deep, so every asset path is **root-relative** (`/style.css`, `/images/...`) —
which is exactly why opening one by double-clicking shows an unstyled page:
`/style.css` resolves to your drive root. To see it on your computer before
uploading, double-click `PREVIEW.cmd` (see *Local preview*).

A `.htaccess` ships with each clean build. It strips trailing slashes, maps
bare paths to their `index.html`, and 301s every old URL — including
`/drops`, `drops.html` and `geocache.html` → `/caches`, since that page was
renamed (twice), not just re-pathed.

Both are generated by `build.py` from one source, so they cannot drift apart.
**Edit the build script, not the output folders** — re-running wipes and
regenerates both.

```bash
python build.py
```

It needs two things, and finds both on its own:

| | Where |
|---|---|
| The 2026-07-06 build it derives from | `_source/website-fixed/` (bundled here) |
| The brand kit | `Desktop\PN0VA` — the sibling folder. If it isn't there, the snapshot in `_source/brand-kit/` is used |

Change anything in `PN0VA` and re-run; both variants pick it up. The source is
bundled rather than referenced so this folder stays self-contained and the
script keeps working years from now.

### The server

The `.htaccess` needs Apache or LiteSpeed with `AllowOverride All`, the usual
shared-hosting setup. It turns off Apache's own trailing-slash redirect
(`DirectorySlash Off`): the pages are folders served at URLs without a slash,
and the two rules redirected each other forever.

**Turn on HTTPS.** Once `https://pn0va.com` opens with a padlock, use the host's
*Force HTTPS* switch, or uncomment the three lines under `# HTTPS.` near the top
of `.htaccess` (and the `Strict-Transport-Security` line). It ships switched off
only because forcing HTTPS on a site with no certificate takes the site down.

Its security headers let nothing on the site use the camera or microphone,
and location only for the Caches page's own **Near me**, which the browser
still asks about first. (Until 2026.10.18 they forbade location outright,
so Near me could never work on the server, only in the preview.)

### The street map

The street map is **served by the site itself**. Carto began answering
keyless requests with "API key required" tiles, which blanked the map; the
site no longer asks Carto (or anyone else) for anything.

- `maps/drops.pmtiles` holds OpenStreetMap streets, water, parks, buildings
  and names around the sites: close-up detail within 4 km of each site
  and a wider view 30 km out. One file, read in small pieces, so a visitor
  downloads only what they look at. A site's page shows it as a street map,
  and the globe draws the same streets once it comes in close to a site.
  (The map's files keep the names they had when the page was Drops; no
  visitor sees them.)
- `drops-map.js` paints it in the site palette with protomaps-leaflet
  (`vendor/protomaps-leaflet/`, BSD licence), inside the same Leaflet map, so
  the rings, marker, graticule and recenter button are unchanged. The
  streets are red, so the grid, the scale and the landmarks read at a
  glance: highways in the brand red, main roads a shade darker, side
  streets darker again and lanes and paths darkest. Railways are taupe,
  buildings taupe on slate ground, parks a dark olive, water near black,
  and the names bone and linen. The site is a bone diamond with a red glow,
  inside bone rings at 50, 100 and 250 m; zoomed out, a ring's label gives
  way where it has no room, and on a map as narrow as a phone's the labels
  go.
- No key, no usage limits, no account. The data is © OpenStreetMap
  contributors (ODbL); the attribution on the map is required and in place.
  On a map as narrow as a phone's it folds to a small **©** a few seconds
  after the page opens, or as soon as the map is moved, so it doesn't
  cover the streets; a tap on it opens it again.

**The map in this folder** was made 2026-09-28 from OpenStreetMap data of
2026-09-27: 10.8 MB, covering the three San Francisco sites. A visitor
who looks at all three downloads about 200 KB of it.

**One map file serves every site, and a new site gets its map by
itself.** Add the site to `drops.html` and run `python build.py`. If it is
more than about 3 km from every site the map was made for, the build first
fetches the area around each site from the newest daily world map
published by Protomaps (build.protomaps.com), then builds. Each site gets
its own area, so sites in two cities cost two small areas, not everything
between them. A test site in Mesa, Arizona added 6 MB to the map and under
30 seconds to the build. A new cache at a site you already have needs no
map at all. Upload the new `maps/drops.pmtiles` along with the rest of the
folder.

The build needs two Python packages for that, installed once:

```bash
pip install pmtiles requests
```

Without them, or offline, the build carries on with the map it has and names
the sites it doesn't cover; the page shows those on plain ground, and the
globe stops at 64x over them. With no map file at all, it shows the rings
and marker on plain ground plus a link to the site on OpenStreetMap, not
error tiles. `python tools/make-map.py` remakes the map on demand, for
instance to pick up newer streets.

**The server must send parts of files** (HTTP "range requests"). Apache,
LiteSpeed, Netlify, GitHub Pages and Cloudflare all do, and so does the
preview (see *Local preview*). Python's `http.server` does not, and a page
opened by double-clicking cannot read a file in parts at all: both show the
rings on plain ground instead of streets.

### The Caches page: the world, then a site

P_N0VA hides small things in plain sight, each marked with a P_N0VA
sticker, at a few **sites**: places it comes back to again and again. What
is hidden at a site on one day is a **cache**, one thing or several, with
its **log**: what is inside, and why. The page has photos of every site
and of what is inside every cache, so there are no hints. The nav and the
home page's menu call it **Caches**, and it is at `pn0va.com/caches`; the
old addresses (`pn0va.com/drops`, `drops.html`, `geocache.html`) forward
there, links to one site or cache included. It is one page with two
screens.

| On the page | What it is | Called before |
|---|---|---|
| **Site** | a place things are hidden, again and again: SITE 03, TELEGRAPH HILL | Cache (and before that, zone and point) |
| **Cache** | what is hidden at a site on one day: CACHE #003 | Drop |
| **Photos** | the site's own photos of the place | Spot |
| **Log** | a cache's story: what is inside, and why | Transmission |
| **Found** | someone has found the cache | Claimed |
| **How it works** | the short note on all this, at the right of a site's bar | What is a drop? |

- **The world** (`pn0va.com/caches`): the list of sites, in order by
  number, each with its number and name, a line or two on what the site
  is and where, and, short under that, how many caches are hidden there
  and the latest one's title; and a globe with a mark for each. It opens
  with no site chosen, the globe turned to where the sites are.
  - **Sort**, over the list, puts it another way: **Newest** (the latest
    cache first), **Name**, **City**, **State** or **Country** (under a
    heading for each place, from each site's `data-city`, `data-state`
    and `data-country`), or **Near me**: nearest first, each row saying
    how far, in miles in the US and UK and kilometres elsewhere. The
    browser asks before it says where you are, and that stays in the
    page; refused or not found, the list stays as it was and says why.
    The menu names the default, **Number (default)**; while another
    order is chosen the menu is lit and **RESET** sits beside it, one
    click back to the default. A reload starts in number order again,
    and the arrow keys go down the list as it is shown.
  - **Choose a site in the list** (a click, Enter, or the arrow keys down
    it) and the globe flies in to it, the site in the middle, close enough
    to see its city and the streets around it (64x where the street map
    doesn't reach). Already closer, it keeps your zoom.
  - **Click a site on the globe** and the globe stays where it is.
  - Either way a prompt opens beside it: what the site is and where, its
    coordinates, then, short, how many caches, when the latest was hidden
    and how long ago and the latest one's number and title, and **OPEN
    SITE**. Its ×, Esc or a click on bare globe closes it.
  - **The zoom buttons**, at the globe's top left, are its only ones:
    **+** and **−** a doubling at a time, every quick press counted, and
    the globe button under them back out to the whole globe. They are big,
    framed in red, lit solid red when pointed at, and dimmed once there is
    nothing left to do. Near a site, + goes on down to street level.
  - **OPEN SITE** is the only way in: the globe dives, flashes, and the
    site's windows fly in. Pointing at a row only marks its site on the
    globe, and a double-click on a site opens nothing.
  - On a phone the globe is too small to carry the prompt, so the chosen
    site's row opens up underneath instead, with the same (but for where
    it is, which its page shows) and OPEN SITE the width of the list. A
    second tap on the row closes it.
- **A site** (`pn0va.com/caches#03`): one bar along the top, then four
  windows in a grid, none over another.
  - **The bar**, one row: **WORLD MAP**, solid red, at its left; the
    site's number and name (SITE 03 TELEGRAPH HILL) and, beside them,
    what the site is and where, in a line or two; **How it works** at its
    right.
  - **Map** and **Photos**, side by side and always in view: the street
    map, at street level with the site's mark in the middle and its
    coordinates in its head (a link to the place on OpenStreetMap), and
    the site's own photos of the place, one place however many caches are
    hidden there, each with its date on it.
  - **Caches**, under the map: the caches hidden there, the page's one
    menu, newest first, a line each: its number, title and date, NEW or
    FOUND, and a small wedge at its end.
  - **Cache**, beside the list: the chosen cache, or, with none chosen,
    how to choose one.
  - **Choose a cache** (a click, or Enter on it) and it flies into its
    place: a photo of what is inside, with the thing's name under it and
    arrows through everything in the cache, beside when it was hidden,
    FOUND or NEW, and its log. That is all that changes: the map, the
    photos and the list stay as they are, the chosen row marked and its
    wedge now a solid red **HIDE ✕**. Choose another in the list (or move
    down it with the arrow keys) and its place shows that one instead.
  - **Choose the open cache again** (its row's HIDE, the page's only
    one), Esc, or the browser's Back puts it away, and its place says how
    to choose one again.
  - **WORLD MAP**, Esc with no cache open, or Back pulls back out to the
    globe, where that site is still chosen.
  - The street map has + and −, and a reticle that takes it back to the
    site as it opened.
  - The four windows share the screen, down to a laptop's short browser
    window (1350x561) with nothing scrolling; the list and the cache, the
    windows that are read, have the larger share. A long list scrolls in
    its window.
  - **On a phone** (any screen under 900px wide or 560px tall) the page
    scrolls: the bar, then the map and the photos side by side as two
    squares (from 600px wide, a little under half the screen tall), then
    the list. A cache opens under its row, the rest of the list carrying
    on below it: what is inside, then its facts and log, side by side
    where there is room. While you read it, its row stays pinned under
    the site's nav, so its HIDE is always to hand. On a map that narrow,
    its head keeps the OpenStreetMap link and drops the coordinates.

**The photos.** A site's photos and what is inside a cache work alike.
Where there is more than one, arrows at the photo's sides and a swipe
across it go through them, earliest first and round again from the last,
and so do the left and right arrow keys once the photo or an arrow has
the focus (Tab to it, or click an arrow); with one, or none, there are no
arrows. A site's photo has its date on it, and with more than one the
window's head counts them (2/3); a photo of what is inside has the
thing's name under it (or the date, for a thing with no name), and the
count beside that. The photo itself opens
nothing: a click on it leaves you on the page. With no photo yet, a note
says so, and a thing that is named keeps its name under it. A photo and
its words change together: turned to one still on its way, the photo
before stays, dimmed, until it comes.

**What is inside.** A cache's `data-inside` names what is in it, in a few
words, several things separated by semicolons. The names go with the
photos in order: the first photo shows the first thing named, the second
the second, and the arrows go through them all. One name with several
photos: they are all photos of that one thing. A thing named with no
photo yet shows the placeholder and its name, so it is still there to
step to.

**How it works**, at the right of a site's bar, says in two short
paragraphs what a site and a cache are and what a site's page shows, for
whoever wonders.

On a phone held sideways the list sits beside the globe, as on a desktop.

Every site and every cache has its own address. `pn0va.com/caches#03`
opens on site 03 and its list; `pn0va.com/caches#007` opens cache 007 at
the site it is hidden at. Opening a cache adds a step to Back, so Back puts
it away again; choosing another while one is open changes the address
without adding a step, so a link copied from there opens on that cache.
Reload and sharing work too, and so do links from before:
`pn0va.com/drops#03` goes to `pn0va.com/caches#03`. A site is marked
**NEW** while its latest cache is in its first week (in the list and its
prompt, and on the globe red, with a **!** over it), and that cache is
marked NEW in the site's list and beside its log.

The globe is drawn in the brand palette from `tokens.css`: ember sea, slate
land with built-up areas a shade lighter, ember lakes and rivers, roads in
red (highways brightest), country borders in bone over a dark edge
(thickening as you come in), dashed taupe state lines, ash coasts, a linen
sheen and names, red for the instruments (graticule, rim, pointer, NEW) and
bone for the site you are on.

It is a map: coast, lakes, rivers, the built-up areas of cities, highways
and main roads, country borders, state and province lines, and the names of
countries, states, cities, peaks and landmarks, each named once there is
room for it. It zooms with its **+** and **−** buttons, the mouse wheel, a
pinch, or the + − 0 keys, from the whole globe down to a city (64 times
closer) anywhere, and near a site on down to street level: within 4 km of
a site as close as its street map opens, and within 30 km close enough to
see its main streets. There the globe draws the street map's own streets,
parks, water and neighbourhood names, so the way down from the whole Earth
to the site's corner never cuts to another map. The coastline is redrawn
finer as you come in, so its shape holds and only sharpens, and the grid
of latitude and longitude grows finer with it, down to a thousandth of a
degree. The globe button below the zoom buttons goes back to the whole
globe.

Every site has its own mark, which grows as you zoom in. Sites too close
together to tell apart, like the three in San Francisco, sit on a small
ring around the point they share, each on a thread back to it, in the
order they really lie (Alcatraz on top); zoom in and they move apart onto
their own points. Point at anything for what it is: a site's number and
name, what it is and where, and how many caches and when the latest was
hidden; a city's state or country, a peak's height, a landmark's note. On
a touch screen, tap it. Close in, a landmark's name goes ahead of the city
it stands in (at 64x the Colosseum shows over Rome), but every name gives
way to the sites and the prompt, so the landmarks right beside a site,
like most of San Francisco's, wait until you come in close enough to give
them room. A site whose caches have all been found is drawn hollow.

Its files:

- `drops-world.js`, from `_source/world/`;
- `vendor/world/`: d3-geo, d3-array and topojson-client (ISC licence), about
  60 KB;
- `maps/world/`: the map, from Natural Earth (public domain), at four levels
  of detail, the closer three with rivers, built-up areas and roads. The
  whole globe is one file of 305 KB (109 KB as the `.htaccess` compresses
  it), and the next level, read while the page is idle, one of 1.1 MB
  (390 KB); closer in, the page fetches only the part in view. 22.6 MB in
  308 files. A visitor who zooms all the way in on a site downloads about
  750 KB of it, compressed (650 KB on a phone), and 250 to 420 KB of the
  street map. `tools/make-world/` made it, and only needs running again for
  newer borders or roads (see the top of `make-world.mjs`);
- `maps/landmarks.json`, from `_source/world/landmarks.json`: 148 landmarks
  around the world, each a name, a position, the zoom it appears from (1 is
  the whole globe, 64 the closest away from the sites) and the note shown
  when pointed at. Add your own the same way and rebuild. At 64x the globe
  shows about 300 m to a pixel, so two landmarks a few streets apart can't
  both show: one a city is plenty.

With reduced motion on, the screens change and a cache's windows open and
close without the dive or the flights. With JavaScript off, the world view
stays hidden and the page is the site's frame it always was.

### Adding a cache, or a site

Everything is in `drops.html`, in the brand kit's `drops` folder (or the
snapshot in `_source/brand-kit/drops/`); the comment at its top says the
same. (The file keeps its old name; the build makes the Caches page from
it.) Each site is a `<section class="dp-site">`, and the caches hidden
there are the `<article class="dp-entry">` blocks inside it, newest first.
Sites go newest first too; the world's list puts them in order by number
all the same, or however a visitor sorts it.

```html
<section class="dp-site" data-n="03" data-place="Telegraph Hill"
         data-city="San Francisco" data-state="California" data-country="United States"
         data-lat="37.802139" data-lng="-122.4058" data-zoom="17"
         data-about="Under Coit Tower at the top of Telegraph Hill. Garden stairs, wild parrots, and the city spread out below.">

  <article class="dp-entry" data-n="007" data-placed="2026.10.12"
           data-title="Third Time Up" data-inside="Cassette, side B; Its case">
    <p>Its log: what is inside, and why. A paragraph or two.</p>
  </article>

  <article class="dp-entry" data-n="005" data-placed="2026.09.12" ...>
    ...
  </article>

</section>
```

- **A new cache at a site you have:** copy an `<article>` into the site's
  `<section>`, above the caches already there. `data-n` is the cache's
  number, three digits, one count across all the sites, so each number
  (and the cache's address, `caches#007`, and its photos) belongs to one
  cache only; `data-placed` the day it was hidden; `data-title` its name;
  `data-inside` what is inside, in a few words, several things separated
  by semicolons (`data-inside="Zine, issue 3; Sticker sheet"`). Then write
  its log.
- **A new site:** copy a whole `<section>` to the top, with one cache in
  it. `data-n` is the site's number, two digits; `data-place` its name,
  which heads its page; `data-about` a line or two on the site, what it is
  and what it is like there, which leads wherever the site is listed and
  sits beside its name on its page (the three sites here have one each to
  start you off: rewrite them as you like); `data-city`, `data-state` and
  `data-country` where it is, in words, which the world's list sorts by
  and heads its places with (leave out any that don't apply); `data-lat`
  and `data-lng` where it is, in decimal degrees; `data-zoom` how close
  its street map opens: 17 is street level, 15 or 16 shows more of the
  neighbourhood. Either way the map zooms from 8 out to 19 in.
- **Photos** go in the same `drops/images/` folder, named for what they
  show and the date as MMDDYY. **Photos of the site are the site's**, one
  place however many caches are hidden there: `site3_092326.jpg` is site
  03, photographed 2026.09.23. **What is inside is the cache's**:
  `item4_092326.jpg` is inside cache 004. A second photo the same day
  takes a letter after the date (`site3_092326b.jpg`). The build finds
  them and puts each set in date order, and the names in `data-inside` go
  with the cache's photos in that order (see *What is inside*, above).
  JPEG, PNG, WebP, GIF or SVG; about 1600 pixels on the long side is
  plenty. To choose the photos and their order yourself, list them on the
  site's `<section>` as `data-photos`, or on the cache's `<article>` as
  `data-items`, separated by spaces (`data-photos="images/a.jpg
  images/b.jpg"`, so no spaces in the names); the build leaves those
  alone.
- **From before, and still read:** a `<section class="dp-cache">` (or
  `dp-zone`, or `dp-point`) is a site; `data-itemcap` is `data-inside`,
  `data-claimed` is `data-found`, and a section's `data-spots` is its
  `data-photos`; photos named `cache<n>_` (n a site's number) are the
  site's, and so are photos named `spot<n>_` (n a cache's number) and a
  cache's own `data-spots` or `data-photos`, which go to the site it is
  hidden at; `data-item` is a single photo of what is inside.

Then run `python build.py`. For a site in a new place it fetches the
street map first (see *The street map*). Nothing else needs touching: the
globe, the lists, the prompts and the site's page all read these blocks.

### Marking a cache found

A cache shows no status unless you give it one. Once you know a cache has
been found, add `data-found` with the date to its `<article>` in
`drops.html`:

```html
<article class="dp-entry" data-n="001" data-placed="2026.06.15" data-found="2026.06.28" ...>
```

and run `python build.py`. On its site's page the cache is then tagged
**FOUND** in the list of caches, in place of NEW, and says **FOUND** with
the date beside when it was hidden. The photos are left alone, so later
visitors still see what was inside. Once every cache at a site is found,
the site says **FOUND** in the world list and in its prompt, and turns
hollow on the globe. `data-found` without a date shows **FOUND** alone;
deleting it undoes it. Nothing ever says "not found". (`data-claimed`,
from before, does the same.)

Cache 001's log says it was recovered on 2026.06.28, but it is not marked:
add `data-found="2026.06.28"` to it if it should show.

### The About page: a status card

The About page is one window in the style of an old JRPG's character
card: the portrait at its top left; beside it the name (**P_N0VA, THE
OPERATOR**), the year it began with an orb for each skill (point at one
for its name), the class (**Creative Developer**) and its kinds; under
those a command menu, **BIO**, **SKILLS** and **SITE**, with the pointing
hand of the old menus at the one chosen and the bar beside it saying what
it is; then the text window, showing the chosen part; and **LV**, the
years since it began, in the box on the text window's corner.

- **Choose a command** with a click, or the arrow keys once the menu has
  the focus (Home and End go to the ends). Only the text window changes,
  and it keeps its height, so nothing jumps.
- **SITE** lists the site's pages, the store only in the build that has
  one.
- On a phone the card is the width of the screen, the portrait and the
  name still side by side.
- With JavaScript off every part shows, one under another; with reduced
  motion the hand keeps still.

It is all in `_source/website-fixed/about.html`, and the comment at the top
of the card says what is what: the portrait is
`images/about/portrait-placeholder.svg` (put your own, about 300 x 340, in
`_source/website-fixed/images/about/` and change the name); each orb's
`title` is the skill it stands for; a command is a button (its
`data-help` is the bar's line) and the section it opens; `data-since` is
the year the level counts from. `about.js` runs the menu, and the card's
styles are at the end of `page-style.css`. The words are still the
placeholders from before (they still say "geocaching adventures"):
rewrite them as you like.

### The test kit's phone view

`python build.py --test-kit` builds the site with a **PHONE VIEW** switch
at the top right of every page (on a desktop window 1200px wide or more).
It opens the page in a phone-sized frame, with the phone layout, to see it
without a phone: **Phone** (390x844), **Small**, **Large** and
**Tablet**; **Turn sideways**; **Actual size** (100%, the frame's area
scrolling, where the window is too short for the phone; otherwise it is
scaled down to fit); **Reload**; the frame's address, kept after the
page's own `#` so a reload stays there; and **Desktop view**, the same
page full size. The mouse stands in for a finger: drag across a photo to
swipe it.

Only the demo kit is built that way. **Never upload a build made with
`--test-kit`**: run `python build.py` again for the site. A plain build
has no trace of it; its parts are in `_source/test-kit/`.

## Local preview

**Double-click `PREVIEW.cmd`** (Windows). Pick a build from the list and the
site opens in your browser at `http://localhost:8940`, served the way the web
host will serve it:

- `/caches`-style addresses, plus the redirects and the missing-page rule,
  read from that build's own `.htaccess`;
- the street map;
- nothing cached, so after a rebuild a reload shows the new files.

Nothing to install: it runs on the PowerShell that comes with Windows. Leave
its window open while you look around, and close it to stop. To preview a
folder kept somewhere else, such as an unzipped upload, drag the folder onto
`PREVIEW.cmd`. For the phone layout, press F12 in the browser, then
Ctrl+Shift+M.

The first time, Windows may warn that the file came from the internet: click
**More info**, then **Run anyway**. If it still won't run, right-click the
zip you downloaded, choose **Properties**, tick **Unblock**, and unzip again.

On a Mac or Linux, or from a terminal, the same preview is
`python tools/preview.py` (add a build name, e.g. `no-store-clean`, to skip
the list). It needs Python and nothing else. `tools/preview.ps1` is the server
behind `PREVIEW.cmd`; keep the two in step.

If you use `.claude/launch.json` (`site-shop`, `site-noshop`), it runs
Python's plain `http.server`: no clean addresses and no street map. Point it
at `python tools/preview.py with-store --no-browser --port 8940` instead.
